## 3. Якість

Парне порівняння на одних і тих самих зображеннях (`b` — INT8 правильний, FP32 помилився; `c` — навпаки):

$$
\Delta_{acc} = \frac{b - c}{n}, \qquad SE(\Delta_{acc}) \approx \frac{\sqrt{b + c}}{n}
$$

Правило інтерпретації: якщо $|b - c| \le 2\sqrt{b + c}$, різниця не відрізняється від шуму.

| Варіант | `macro-F1` | `accuracy` | Узгодження з FP32 | $b$ | $c$ | $\Delta_{acc} \pm SE$ | Результат |
| :--- | :-: | :-: | :-: | :-: | :-: | :-: | :--- |
| FP32 | 0.8919 | 0.8901 | 1.0000 | 0 | 0 | $0$ | базовий варіант |
| INT8 | 0.8898 | 0.8881 | 0.9900 | 6 | 9 | $-0.0020 \pm 0.0026$ | не відрізняється від шуму |

Перевірка порога: $|b - c| = |6 - 9| = 3 \le 2\sqrt{6 + 9} \approx 7.75$. Зміна якості не відрізняється від шуму, згода передбачень становить 99.00%.

**Порівняння парної похибки з похибкою однієї моделі.**  
Стандартна похибка `accuracy` однієї моделі на $n = 1502$ становить $SE = \sqrt{p(1-p)/n} = \sqrt{0.8901 \cdot 0.1099 / 1502} \approx 0.0081$. Парна похибка $SE(\Delta_{acc}) = 0.0026$ менша більш ніж у 3 рази. Причина в тому, що обидві моделі оцінюються на тих самих зображеннях і мають згоду 99%: спільна дисперсія вибірки скорочується, і в похибку різниці входять лише $b + c = 15$ спірних зображень замість усіх $1502$.

## 4. Дослід із потензорними вагами

### Діапазони каналів згорток у `lab4_fp32.onnx`

Для кожного з 20 вузлів `Conv` обчислено $\alpha_c = \max |w|$ по кожному вихідному каналу $c$ та відношення $r = \max_c \alpha_c / \text{median}_c \alpha_c$.

**Топ-3 згортки за $r$:**

| Вузол `Conv` | $r$ | $\log_2 r$ |
| :--- | :-: | :-: |
| `/conv1/Conv` | 6.67 | 2.74 біта |
| `/layer3/layer3.1/conv2/Conv` | 5.90 | 2.56 біта |
| `/layer3/layer3.0/downsample/downsample.0/Conv` | 4.92 | 2.30 біта |

**Медіана за всіма 20 згортками:** $r = 3.44$, що відповідає втраті **1.78 біта** точності для медіанного каналу при переході до потензорної квантизації.

### Прогноз до запуску

У ResNet-18 розкид каналів помірний (максимум $r = 6.67$, медіана $r = 3.44 \approx 1.78$ біта, на відміну від $r \approx 90$ у MobileNetV3). Тому перехід до `per_channel=False` має помітно знизити згоду з FP32 (через грубішу сітку квантизації для частини каналів), але суттєвого падіння `macro-F1` понад шум не очікується.

### Результат запуску (`lab4_int8_per_tensor.onnx`)

Час підготовки та квантизації (`per_channel=False`): 3.12 с.

| Варіант | `macro-F1` | `accuracy` | Узгодження з FP32 | $b$ | $c$ | $\Delta_{acc} \pm SE$ | Результат |
| :--- | :-: | :-: | :-: | :-: | :-: | :-: | :--- |
| INT8 (`per_channel=False`) | 0.8911 | 0.8895 | 0.9867 | 9 | 10 | $-0.0007 \pm 0.0029$ | не відрізняється від шуму |

**Зіставлення з прогнозом і пояснення.**  
Прогноз підтвердився частково: згода з FP32 справді знизилася, але лише на 5 зображень — з `0.9900` до `0.9867` (кількість розбіжностей зросла з 15 до 20, з них $b + c = 19$ змінили правильність), а `macro-F1` та `accuracy` очікувано залишилися в межах шуму ($|9 - 10| = 1 \le 2\sqrt{19} \approx 8.72$).  
Згода реагує на квантизацію чутливіше, ніж `macro-F1`, бо вона рахує будь-яку зміну передбачення на межових зображеннях. Натомість у різниці $b - c$ та в `macro-F1` випадкові перекидання класу в обидва боки ($b = 9$ виправлень і $c = 10$ нових помилок) майже повністю взаємно компенсуються.

## 5. Затримка на CPU

Протокол: сесії створені заздалегідь (`CPUExecutionProvider`, 1 потік), один і той самий вхід ($1 \times 3 \times 160 \times 160$, перше зображення `test`), 3 раунди (FP32 → INT8), у кожному 20 прогрівальних викликів і 100 вимірів через `time.perf_counter()`. Вимірювання проводилися на стаціонарному ПК, важкі фонові програми були закриті.

### Параметри середовища

| Параметр | Значення |
| :--- | :--- |
| Процесор | 12th Gen Intel(R) Core(TM) i5-12400 |
| Операційна система | Windows 11 (10.0.22631) |
| Python | 3.12.15 |
| PyTorch | 2.11.0+cu128 (у `requirements.txt` зафіксовано `2.11.0` для сумісності на CPU/macOS) |
| ONNX | 1.23.2 |
| ONNX Runtime | 1.32.0 |
| Кількість потоків | 1 (`intra_op=1`, `inter_op=1`) |
| Розмір пакета | $B = 1$ |

### Результати вимірювань

| Варіант | Файл, МБ | p50, мс | p95, мс | p50 за раундами, мс |
| :--- | :-: | :-: | :-: | :-: |
| FP32 | 44.71 | 15.49 | 17.03 | 15.54, 15.56, 15.42 |
| INT8 | 11.30 | 4.73 | 5.84 | 4.71, 4.65, 4.79 |

- **Зменшення розміру файлу:** $44.71 / 11.30 = \mathbf{3.96\times}$
- **Прискорення за p50:** $15.49 / 4.73 = \mathbf{3.28\times}$
- **Прискорення за p95:** $17.03 / 5.84 = \mathbf{2.92\times}$
- **Правило інтерпретації:** відрізки $[\min, \max]$ для p50 по раундах — `[15.42, 15.56]` мс (FP32) та `[4.65, 4.79]` мс (INT8) — **не перетинаються**, отже зміна затримки є надійно виміряною.

## 6. Висновок

1. **Зміна ресурсів і затримки.** Статична квантизація зменшила розмір файлу моделі в 3.96 раза (з 44.71 МБ до 11.30 МБ) і прискорила інференс на CPU у 3.28 раза за медіаною p50 (з 15.49 мс до 4.73 мс) та у 2.92 раза за p95 (з 17.03 мс до 5.84 мс). Відрізки p50 по раундах не перетинаються (`[4.65, 4.79]` проти `[15.42, 15.56]` мс), тому прискорення надійно виміряне.
2. **Якість.** Зміна якості не відрізняється від шуму: `macro-F1` змінився з `0.8919` до `0.8898`, $\Delta_{acc} = -0.0020 \pm 0.0026$ ($|b - c| = 3 \le 2\sqrt{15} \approx 7.75$), а згода передбачень із FP32 становить 99.00%.
3. **Пояснення прискорення через модель даху Roofline та апаратні ядра.** ResNet-18 на вході $160 \times 160$ виконує приблизно $0.93\text{ GMAC} \approx 1.86\text{ GFLOP}$. За p50 = 15.49 мс варіант FP32 досягає $\approx 120\text{ GFLOP/с}$ при теоретичному піку одного ядра i5-12400 з AVX2 близько $140\text{ GFLOP/с}$ (32 FLOP/такт при ~4.4 ГГц). Арифметична інтенсивність за вагами становить $\approx 1.86\cdot 10^9 / 44.71\cdot 10^6 \approx 42\text{ FLOP/Б}$, що значно вище за критичну інтенсивність $I_{\text{крит}}$ одного ядра — отже, згортки обмежені обчисленнями, а не пропускною здатністю пам'яті. Тому прискорення визначається не зменшенням байтів ваг (3.96×), а наявністю цілочисельних інструкцій **AVX-VNNI**, які теоретично дають до 4× більше INT8-операцій за такт. Фактичне прискорення **3.28×** нижче за теоретичні 4× через накладні витрати формату QDQ (`QuantizeLinear` / `DequantizeLinear`), квантизацію активацій і шари, що лишаються у FP32.
4. **Придатність INT8-моделі.** Для процесора **Intel Core i5-12400** та **ONNX Runtime 1.32.0** INT8-модель придатна до практичного використання: вона дає майже чотирикратну економію пам'яті й понад трикратне прискорення без статистично значущої втрати якості.
